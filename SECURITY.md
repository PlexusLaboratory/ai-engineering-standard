# Security Policy

## Supported versions

This repository does not yet publish versioned releases. Security fixes apply to the default maintained version once a release policy is established.

## Reporting a vulnerability

Please do **not** disclose suspected vulnerabilities in public issues, pull requests, discussions, chat rooms, or commits.

Use GitHub’s private vulnerability-reporting feature if it is enabled for this repository. If it is not enabled, contact a project maintainer through an agreed private channel before publishing details. Project owners must add a durable private contact method before making this repository public.

Include, when safe to share:

- a concise description and affected component;
- impact and realistic attack prerequisites;
- reproducible steps or a minimal proof of concept;
- affected versions, environments, and configurations;
- suggested mitigation, if known.

Do not include credentials, personal data, production data, or destructive exploit payloads.

## Response expectations

Maintainers should acknowledge a valid report promptly, assess severity and scope, communicate a safe remediation timeline, and credit reporters only with their consent. Fixes should include regression coverage where practical and coordinated disclosure after affected users can protect themselves.

## Safe-harbor intent

Good-faith security research that avoids privacy violations, service disruption, data destruction, and access beyond what is necessary is welcome. This statement is not a legal authorization; project owners should publish a jurisdiction-appropriate safe-harbor policy and contact method if public vulnerability research is expected.
