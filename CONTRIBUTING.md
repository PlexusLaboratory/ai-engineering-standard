# Contributing

Thank you for improving this project. Contributions should make the repository safer, clearer, or more useful without increasing unnecessary complexity.

## Before you begin

1. Read [INSTRUCTIONS.md](INSTRUCTIONS.md), [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md), and this guide.
2. Search existing issues and discussions before opening a duplicate request.
3. For a substantial feature, API change, migration, or security-sensitive work, discuss the intended outcome before investing in implementation.
4. Do not include secrets, private data, copied proprietary content, or unrelated changes.

## Contribution workflow

1. Describe the problem, expected outcome, affected users, and constraints.
2. Make the smallest coherent change that solves it.
3. Update tests and documentation whenever the change affects behavior, configuration, interfaces, or operations.
4. Run checks appropriate to the task’s risk. Record checks you could not run and why.
5. Submit a focused pull request using the repository template.
6. Respond constructively to review feedback and keep the branch current when asked.

## Quality expectations

- Follow the design, security, testing, and compatibility rules in [INSTRUCTIONS.md](INSTRUCTIONS.md).
- Preserve backward compatibility unless the change explicitly documents a breaking transition.
- Include negative and boundary cases for meaningful logic changes.
- Keep commits and pull requests narrowly scoped; separate refactoring from behavior changes where practical.
- Write clear, inclusive documentation in the language(s) required by the changed document.

## Reporting defects and proposing features

Use the bilingual GitHub issue forms in [`.github/ISSUE_TEMPLATE/`](.github/ISSUE_TEMPLATE/). Do **not** use public issues for suspected vulnerabilities; follow [SECURITY.md](SECURITY.md) instead.

## Review and merge

Maintainers review for correctness, security, scope, tests, documentation, compatibility, and maintainability. A pull request may be declined when its benefit does not justify its complexity or maintenance cost. Approval does not transfer responsibility for undisclosed risks or external side effects.

## License and contributor agreement

No repository license has been selected. Do not submit code or content unless you have the right to contribute it. Once a license is chosen, contributions will be subject to its terms unless maintainers publish a different contributor agreement.
