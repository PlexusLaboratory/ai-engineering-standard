# Governance

## Maintainer responsibility

Until named roles are published, the repository owner and explicitly authorized maintainers are responsible for triage, review, releases, security coordination, and policy updates. They must act in the project’s interest, disclose material conflicts when practical, and avoid using authority to bypass the standards in [INSTRUCTIONS.md](INSTRUCTIONS.md).

## Decision-making

Default decisions are evidence-based and proportionate to impact:

- routine, reversible changes may be accepted after normal review;
- public API, architecture, dependency, security, and compatibility changes require documented rationale and appropriate validation;
- high-risk or irreversible changes require explicit owner approval, a rollback or recovery plan, and an auditable record of the decision.

When reasonable contributors disagree, maintainers should summarize the options, evidence, trade-offs, and final decision. Consensus is preferred; timely maintainer judgment resolves deadlocks.

## Policy changes

Changes to governance, security, conduct, contribution, or instruction policies should be proposed openly when doing so is safe. Emergency security changes may be made privately first and documented after disclosure is safe.

## Project ownership and succession

Project owners should name maintainers, define access levels, maintain at least two trusted administrators for critical public projects, and document a transfer plan. Do not add a `CODEOWNERS` file until real GitHub accounts and review paths are known.
